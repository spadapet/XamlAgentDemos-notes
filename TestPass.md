# Automated demo test pass

Each demo is run by an automated harness against fastmain VS, with Copilot Chat in Agent + Autopilot mode.

For each run, the harness:
1. Resets the repo and presses F5 on the demo.
2. Starts a new chat and sends the DEMO.md prompt verbatim.
3. Waits for the agent to finish, then asks a feedback follow-up.
4. Saves `events.jsonl`, `transcript.md` (with images), `fix.diff`, `dialogs.log` and `runner.log` in `test-runs/<Demo>/<tag>/`.

DEMO.md answer keys are used for grading only. The chat agent never sees them.

The harness scripts live in the Copilot CLI session folder (`files\harness`).

## Harness notes
- Find-SessionDirForPrompt now also matches the JSON-escaped form of the prompt snippet (backslashes doubled, quotes escaped); a prompt with a path failed to match (PixelPerfect run1).
- `Set-Autopilot` sometimes ran before the mode menu had populated ("Autopilot not set"). It now retries up to 4 times.
- A new chat session defaults to Interactive mode, so the harness switches it to Autopilot each time.
- A locked workstation blocks UI Automation input. A keep-awake mouse nudge runs during the pass.

## Finding #115: get_element_bounds reported everything as clipped on a high-DPI secondary monitor
compact1 fixed all 4 causes in 1.7 min, then spent 4 more minutes chasing a "clipped footer": every element, even the Window at 0,0, had insideWindowFraction=0 and clippedByWindow=true. Root cause: devenv called GetClientRect/ClientToScreen from a thread that isn't per-monitor aware, so on a 150% monitor (not the system DPI) it got virtualized coordinates while the TAP reports physical pixels. The rectangles never intersected. Fix: a `PhysicalPixelsScope` (SetThreadDpiAwarenessContext PER_MONITOR_AWARE_V2) in XamlAgentImaging.GetClientScreenRect, GetWindowInfo, IsPartlyOffScreen and CaptureWindow (whose DWM frame crop mixed virtualized and physical rects). Hit-test visibleFraction shared the bug. compact2: 4/4 fixed in 1.8 min, no detour.

## LVT usefulness analysis (2026-11-15)
Across 62 runs, the tree tools were used in 56: xaml_find_elements in 47 runs (152 calls), xaml_get_visual_tree in 44 (85 calls, ~18 paging into a subtree). The model uses the LVT mainly to locate elements and get ids, then switches to targeted tools (explain_visibility, explain_property_value, styles, binding failures, audit_styles), which walk the tree internally and return file/line for edits. Find-by-source was rare (7 calls). Deep tree browsing was rare because dumps cost ~6 KB each. Conclusion: the LVT is essential as the foundation (ids + source mapping) but secondary as a browsing tool; invest in targeted queries rather than richer dumps.
